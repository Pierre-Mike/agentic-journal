# Design

Replace the v1 workflow canvas wholesale with a v2 generated by the
`canvas-generator-v2` skill, capturing the post-spec-016 pipeline.

## Approach

1. Assemble a structural spec (nodes, edges, groups) describing the three zones
   — Forward / Feedback / Guardrails — per the locked node inventory.
2. Invoke `canvas-generator-v2` to produce `docs/agentic-workflow.canvas` with
   deterministic positions/sizes/edge routing.
3. Validate: parse JSON, count nodes, check group structure, edge counts/colors,
   and that file nodes reference existing repo paths.

## Files touched

- `docs/agentic-workflow.canvas` — full replacement (RED stub → final canvas).
- `scripts/gates/canvas-valid-v2.ts` — new smoke gate enforcing the v2 acceptance criteria (node count 20-30, three named groups with documented fills, ≥ 5 file nodes, ≥ 1 link node, ≥ 3 dotted-red guardrail edges). Modeled on the existing `scripts/gates/canvas-valid.ts` from spec 005.

## Decisions

- **Full replacement via canvas-generator-v2.** The existing canvas is replaced
  wholesale. canvas-generator-v2's deterministic layout produces consistent
  spacing as content grows. This spec `supersedes: 005-workflow-canvas`.
- **Detailed pre-commit hooks named individually.** `typecheck (RED-skip)` vs
  `spec-lint` is a load-bearing asymmetry from spec 016 — aggregating to
  "pre-commit (4 hooks)" hides the RED-skip nuance and defeats the canvas's
  pedagogical purpose. Total node count ~25, within readable density.
- **Exactly 5 file-type nodes for clickability.** Obsidian Canvas's killer
  affordance is clickable navigation. Cap at 5 to bound visual weight:
  `lefthook.yml`, `scripts/red-commit-gate.ts`, `scripts/trace-scan.ts`,
  `.claude/skills/do/SKILL.md`, `.claude/skills/retro/SKILL.md`. Plus 1 link
  node to the GitHub PR list.
- **`kind: workflow` over `writeup`.** The aligned plan named `kind: writeup`
  but the writeup gate (`scripts/gates/writeup.ts`) requires markdown frontmatter
  + text sections, which a JSON `.canvas` file cannot satisfy. Using `workflow`
  with a dedicated `canvas-valid-v2.ts` smoke gate (mirroring predecessor 005)
  is the minimal deviation that lets `tasks:verify` actually pass. All other
  alignment decisions hold unchanged.

## Risks

- **Skill output drift** — canvas-generator-v2 evolves; output may shift
  between runs. Mitigation: validation step asserts node count, group
  structure, and edge colors against acceptance criteria.
- **File path drift** — referenced repo files may be renamed/moved.
  Mitigation: Step 5/task 2 verifies all 5 paths exist before generation.

## Out of scope

- Any code changes beyond `docs/agentic-workflow.canvas` and the new
  `scripts/gates/canvas-valid-v2.ts` gate script.
- Modifying the `canvas-generator-v2` skill itself.
- Modifying `scripts/gates/writeup.ts` (the kind-deviation above avoids this).
- Other documentation pages (READMEs, blog posts, expertise refs).
